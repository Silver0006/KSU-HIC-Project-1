The Eight Golden Rules of Interface Design

As defined by Ben Shneiderman

  • 1. Strive for consistency
  • 2. Seek universal usability
  • 3. Offer informative feedback
  • 4. Design dialogs to yield closure
  • 5. Prevent errors
  • 6. Permit easy reversal of actions
  • 7. Keep users in control
  • 8. Reduce short-term memory load

3. Offer informative feedback

Have you ever received a error from a program or website? If you've used a computer, it is likely. Error are designed to inform. And the more they inform the better. When designing for user experience, you what an error to be easy to understand. Providing no context can be a quick way to annoy users. Even worse, what if the program doesn't inform you of the error. For example, if you are submitting a document and it fails. Depending on the document, it could be incredibly harmful. Providing descriptive error messages not only benefits your users, but it can help reduce negative impression by providing users with reasonable explanations of why something failed.
